Overview #

Research into the Harvia electric heater we’re planning (7–9 kW range, model TBD) and — the real question — how a controller connects to it, and whether a DIY controller is a realistic substitute for Harvia’s own (expensive) control units.

Short answer: it is not a matter of tapping an on/off switch. Harvia’s “separate control unit” heaters have no switching or thermostat on board — the control unit is the switchgear. Any DIY controller has to replicate three jobs: switch the high-current load (via a contactor), read the temperature sensor, and honor the independent overheat cutoff. That’s very doable, but it’s mains-current work, not a hobby relay on the element wire.

Key points #

  • Harvia heaters come in two families: built-in-control models (thermostat + timer knobs on the unit — e.g. KIP-W, Cilindro PC) and control-unit-required models (e.g. KIP-E, Cilindro PC-E, larger units) that ship with no controls.
  • The control unit is really two boxes: a power/contactor unit (the switching hardware, mounted near the heater) and a control panel (the wall keypad). On the compact Xenio CX30/CX45 these are combined into one box up to 11 kW.
  • The heater itself is essentially elements + a terminal block + a pocket for the temperature sensor. All intelligence lives in the control/power unit.
  • The load is switched by a contactor, not by the controller’s electronics directly. 8 kW @ 240 V ≈ 33 A — far beyond any PCB relay. The control panel’s low-current signal energizes the contactor coil, which throws the heater power.
  • The temperature sensor (Harvia WX232) contains two elements: an NTC thermistor (22 kΩ @ 25 °C) for temperature reading, and a separate resettable overheat protector (150 °C limiter) wired into a safety circuit — an independent hardware cutoff, not something the software controls.
  • Harvia’s own panel↔power-unit link is a proprietary data cable (RJ10 4P4C). It is not a documented open protocol — so a DIY build replaces the whole control unit, it doesn’t “plug into” Harvia’s panel port.

Details #

The two heater families (pick this deliberately) #

Family Examples (~8 kW) Controls Implication for us
Built-in controls KIP80W, Cilindro PC80 Thermostat + 1–8 h timer on the unit Cheapest, simplest; no easy external automation — you’d be hacking the knob
Control-unit-required KIP80E, Cilindro PC-E, Virta None on heater Designed to be driven by an external unit → this is the family a DIY controller targets

Decision needed: If we want any smart/scheduled/remote control (DIY or Harvia), we should buy a “-E” / control-unit-required heater, not a built-in-control model. A built-in-controls heater is the wrong starting point for a custom controller.

How Harvia’s own system is wired (the architecture to replicate) #

Power and signal are separated into two boxes:

  1. Power unit / contactor box — mounted ~1 ft off the floor near the heater. This is the switchgear. Terminals on the Xenio CX30/CX45:
    • L1/L2 in — incoming power from the breaker.
    • L1/L2 out (arrow-marked) — power out to the heater.
    • A1/A2 — 14 ga safety leads to the heater’s high-limit circuit (mandatory).
    • Temperature sensor leads — land on the control card in order blue, white, red, yellow (NTC pair + overheat-protector pair).
    • Left RJ jack — data cable to the wall control panel (right jack is unused).
    • Neutral — only needed if switching a light/accessory.
  2. Control panel — the wall keypad. Sends a low-current command down the RJ10 data cable; the power unit’s contactor does the actual high-current switching.

So the signal chain is: panel → data cable → power-unit logic → contactor coil → contactor throws L1/L2 → heater elements. The NTC feeds temperature back to the logic; the overheat protector sits in a hardwired safety loop that can drop the contactor regardless of the software.

Contactor sizing matters: Harvia’s own K1 contactor spare is rated ~25 A per pole, and the combined CX30/CX45 power unit tops out at 11 kW. Above that Harvia moves to separate/larger contactor units (WX-series). Our 7–9 kW single-phase load (~30–37 A) is right at the edge where a single properly-rated contactor (≥40 A, sauna/heating duty) is required.

What a DIY controller actually has to do #

It is not “hook up to the on/off switch.” A control-unit-required heater has no switch to tap. A DIY controller is the control unit, so it must provide:

  1. Contactor switching — a mains-rated contactor (not a PCB relay) sized to the heater’s full current with margin. The microcontroller only drives the contactor coil (e.g. via a small SSR or pilot relay). This is the single most important safety point: the Arduino/ESP never carries heater current.
  2. Temperature sensing — either read Harvia’s NTC (22 kΩ @ 25 °C) via a divider, or add a probe rated for sauna temps (DS18B20 tops out ~125 °C — marginal for a 150 °C+ sensor pocket; a K-type thermocouple + amp, or a PT100/PT1000, is the more honest choice at sauna temperatures).
  3. Independent overheat cutoff — keep the WX232’s resettable overheat protector (or an equivalent thermal fuse/limit) in series with the contactor coil as a hardware interlock, so an overheat drops the contactor even if the software hangs. This must be independent of the MCU.
  4. Fail-safe design — wiring must fail open (heater OFF) on loss of MCU power, sensor fault, or coil-drive fault. (Community projects flag cheap relay boards that fail closed — unacceptable for a heater.)
  5. Session timer / max-on limit — code requires heaters to auto-shut-off after a set period; the controller must enforce this.

Prior art (DIY is proven, but treat as reference only) #

  • Kobra/arduino-sauna (GitHub) — Arduino Uno + DS18B20 probe + RTC + a single relay driving furnace power, explicitly built around a Harvia furnace. Demonstrates the pattern but uses a low-current relay and a probe under-rated for full sauna heat.
  • Arduino/element14 forum threads describe the correct pattern: SSR drives a contactor coil, flyback diodes on DC coils, decoupling caps to survive contactor EMI.
  • ESP32 + WiFi would give us MyHarvia-style remote/scheduling for a fraction of the cost of Harvia’s WiFi panel — the appeal that’s driving this DIY question.

Warning (safety- & code-critical): This is a fixed-wired 30–37 A appliance. A DIY controller means we are the ones responsible for contactor sizing, the overheat interlock, GFCI/disconnect, and fail-open behavior. Many jurisdictions expect a listed control on a sauna heater; a home-built controller may not pass inspection or satisfy insurance. Verify against local code before committing (see ../02-planning/permits-and-code.md). A hybrid — Harvia power/contactor unit doing the switching + our own low-voltage logic driving its coil — may be the safest path to “DIY smarts without DIY mains switchgear.”
